# 개인정보 실습-9: 마스킹, AES-GCM, HMAC 은 무엇을 되돌릴 수 있나

블로그 「개인정보 암호화」 9편(`posts/Work/security/pii-encryption/09_9편 - 마스킹과 암호화는 무엇을 되돌릴 수 있느냐로 고른다.html`)의 실습이다.
같은 입력 여섯 행(A B A C A B)에 세 방식을 적용해 한 화면에 찍는다.

| 확인 | 무엇을 보나 |
|---|---|
| [2] 되돌리기 | 저장된 값에서 원문을 다시 얻을 수 있나 |
| [3] 서로 다른 출력의 개수 | 같은 값이 같은 출력이 되나 (등치 조회 가능성, 빈도 노출) |
| [4] 등치 조회 | `WHERE col = f(A)` 가 정답 행만 찾나 |
| [5] 키 교체 | 키를 k1 에서 k2 로 바꾸면 기존 행은 어떻게 되나 |
| [6] 문장 속 개인정보 | 정규식 마스킹과 문장째 암호화의 차이 (이름과 번호가 섞인 가짜 메모 한 줄) |
| [7] 저장 길이 | 컬럼 크기를 잡을 때 필요한 숫자 |

- 데이터는 전부 가짜다. 계좌번호는 `999-` 로 시작하는 실습용 형식이고 이름은 `홍길동` 하나다.
  C 는 A 와 끝 여섯 자리가 같게 골랐다(마스킹하면 겹친다).
- 키는 실습용 문자열의 SHA-256 으로 만든 고정 키다. 운영 시스템의 키·암호문 형식과 관계없다. 암호문 표시 `lab9$키ID$` 도 실습용이다.
- AES-GCM 은 AES-256, 행마다 새 96비트 IV, 128비트 태그, 키 ID 를 AAD 로 넣는다.
- HMAC 은 HMAC-SHA256 을 Base64 로 저장한다.
- **이 실습은 토큰이나 암호문에서 원문을 역산하거나 후보를 대입하지 않는다.** 키 없는 해시의 약점은 글에서 공개 자료로만 다룬다.

## 돌리기

```bash
cd labs/security/pii-09-mask-vs-encrypt
java src/MaskVsEncrypt.java          # JDK 11 이상, 외부 라이브러리 없음 (실습은 OpenJDK 25.0.3)
./scripts/run.sh 1                   # 같은 출력을 out/run-1.txt 에도 남긴다
```

암호문(AES-GCM 열)은 IV 를 매번 새로 뽑으므로 실행마다 다르다. 나머지 숫자(되돌린 행, 출력 개수, 조회 결과, 빈도, 키 교체 결과, 길이)는 실행마다 같다.
HMAC 토큰은 키가 고정이라 실행마다 같다.
