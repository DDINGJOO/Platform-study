# 운영 절차서: 주문 서비스

경고의 `runbook_url` 주석이 이 문서의 절을 가리킨다. 명령은 실습 디렉터리에서 친다.

## OrderErrorRatioHigh

**뜻**: 최근 1분 동안 주문 요청 중 5xx 비율이 5% 를 1분 넘게 넘었다. 사용자가 주문을 못 하고 있다. 등급 page.

### 1. 선언과 역할 (2분 안에)
- 장애 채널을 열고 지휘자(IC)를 정한다. 혼자면 혼자가 IC 다.
- `python3 scripts/gd.py event declare "<한 줄 상황>"` 으로 선언 시각을 남긴다.

### 2. 어디가 아픈가: 지표 네 개를 한 번에 본다
```
python3 scripts/gd.py diag
```
| 보이는 것 | 해석 | 다음 |
|---|---|---|
| order가 본 재고 호출 p99 가 크고, 재고 서버 자체 p99 는 작다 | 재고 서버는 빠른데 가는 길이 느리다(네트워크, 프록시) | 3-A |
| 재고 서버 자체 p99 도 크다 | 재고 서버가 느리다 | 3-A 후 재고 담당 호출 |
| 재고 호출 결과가 `error`(연결 거부) | 재고 서버가 죽었다 | 3-A 후 재고 재시작 |
| 재고 호출은 정상인데 실패율만 높다 | 주문 서비스 자체 문제 | 최근 배포 확인, 되돌리기 |

진단 결과는 `diag` 가 자동으로 기록한다.

### 3-A. 완화: 재고 확인을 보류하고 주문을 받는다
원인을 고치기 전에 사용자 영향부터 멈춘다. 재고 확인을 건너뛰고 주문을 '확인 보류'로 받는다(나중에 재고 부족이면 취소 연락이 필요하다는 비용이 있다).
```
python3 scripts/gd.py fallback on
```
1~2분 뒤 `gd.py diag` 로 실패율이 내려갔는지 확인한다. 안 내려가면 IC 에게 알리고 2단계로 돌아간다.

### 4. 상태 공지
- 영향을 받기 시작한 시각, 지금 상태(완화됨/조사 중), 다음 공지 시각을 적는다.
- `python3 scripts/gd.py event comms "<공지 문장>"`

### 5. 원인 제거와 정상 경로 복귀
- 재고 경로 문제를 해결한다(실습에서는 `python3 scripts/gd.py heal`).
- `gd.py diag` 로 order가 본 재고 호출 p99 가 평소(100ms 아래)로 돌아왔는지 본다.
- `python3 scripts/gd.py fallback off` 로 정상 경로로 되돌리고, 2분간 실패율을 지켜본다.
- `python3 scripts/gd.py event resolved "<한 줄>"`

### 6. 사후
- `python3 scripts/timeline.py <run>` 으로 타임라인을 만들고 사후 분석 문서를 연다.

## OrderLatencyHigh

**뜻**: 주문 p99 가 500ms 를 2분 넘게 넘었다. 등급 ticket(근무 시간에 본다).
OrderErrorRatioHigh 와 같이 울렸다면 그쪽 절차를 따른다. 혼자 울렸다면 2단계 표로 어디가 느린지 보고 티켓에 적는다.
