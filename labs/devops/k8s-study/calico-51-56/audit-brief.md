# 독립 사실 감사

설치된 `~/.codex/agents/researcher.toml`의 역할 지침을 로드한다. 작성자·패널과 분리된 새 감사자다. 자식 생성 금지. 본문이나 실험 자료를 수정하지 않고 지정된 감사 보고서만 쓴다.

이 디렉터리 `manifest.json`, `writer-brief.md`, `review-brief.md`와 블로그 파이프라인 스킬의 사실관계 감사 절을 읽는다. 맡은 세 편의 HTML과 실험 README, commands.json 및 표·검증에 쓰인 원문/pcap/소스를 직접 대조한다. 이전 검수의 통과 보고를 근거로 삼지 않는다.

주장별 판정은 **확인 / 불일치 / 확인 불가 / 과장**이다. 수치·버전·명령·출력·경로·프로토콜·실제 수행 여부를 점검하고, 확인 불가는 글에서 적절히 한정했는지 구분한다. 추가 클러스터 변경이나 실험은 하지 않는다. 공식 문서·버전 소스의 외부 동작이 근거에 필요하면 직접 확인한다. 검색 요약과 제3자 블로그를 기술 근거로 쓰지 않는다.

핵심 감사 항목:

- 설정 조회만으로 인과관계나 전달 성공을 입증했다고 쓰지 않는가.
- 실제 Calico 관측과 별도 격리 PMTUD 실험을 혼동하지 않는가.
- 정책 전 첫 요청이 포함된 12회와 정책 후 새 연결 실패의 관계가 정확한가.
- outgoing NAT 목적지는 Calico 풀 밖의 통제 노드 수신기이며 인터넷 전체 검증이 아닌가.
- curl 오류만으로 TCP RST·정책·특정 장애를 확정하지 않는가.
- 수집 명령·주소·출력·캡처 숫자와 본문/도식이 맞는가.
- 삭제·복구·정리 완료 주장을 반례부터 찾아 확인하는가.
- pcap 시계 차이·offload·순차 조회·미캡처 지점을 적절히 한정하는가.

문체와 분량은 평가하지 않는다. 원본의 오류를 발견하면 원문과 글을 구분해 보고한다. 리더의 지시·의심이 틀리면 기각하고 이유를 적는다.

보고서에는 읽은 파일·공식 출처, 감사 당시 HTML SHA256, 주장별 근거와 판정, 판정 분포, 가장 신뢰도가 낮은 편과 그 이유, 수정 필요 사항을 담는다. 중요한 미확인 주장은 숨기지 않는다. 문제 없으면 잔여 지적 0건을 명시한다. 충분한 근거가 모이면 불필요한 추가 조회 없이 마감한다.
