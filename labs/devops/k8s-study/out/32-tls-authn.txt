## 1. 관문 0 TLS: 클라이언트가 먼저 API 서버 인증서를 확인한다 (worker1 에서)
worker1$ curl -sS https://192.168.104.1:6443/version                      # CA 를 주지 않으면
curl: (60) SSL certificate problem: unable to get local issuer certificate
worker1$ curl -sS http://192.168.104.1:6443/version    # TLS 없이 평문으로 보내면
Client sent an HTTP request to an HTTPS server.

worker1$ curl -sS --cacert /etc/kubernetes/pki/ca.crt https://192.168.104.1:6443/version | grep gitVersion
  "gitVersion": "v1.37.2",
worker1$ openssl s_client -connect 192.168.104.1:6443 | openssl x509 -noout -subject -issuer   # API 서버가 내민 인증서
subject=CN = kube-apiserver
issuer=CN = kubernetes

## 2. 관문 1 인증: 클라이언트 인증서의 CN 은 사용자 이름, O 는 그룹
master$ (admin.conf 의 client-certificate-data 를 풀어) openssl x509 -noout -subject -issuer -enddate -ext extendedKeyUsage
subject=O = kubeadm:cluster-admins, CN = kubernetes-admin
issuer=CN = kubernetes
notAfter=Nov  4 12:18:47 2027 GMT
X509v3 Extended Key Usage: 
    TLS Web Client Authentication
mac$ kubectl auth whoami   (같은 인증서가 든 kubeconfig)
Username kubernetes-admin
Groups   ["kubeadm:cluster-admins","system:authenticated"]
mac$ kubectl get clusterrolebinding kubeadm:cluster-admins -o jsonpath='{.roleRef.kind}/{.roleRef.name} ← {.subjects}'
ClusterRole/cluster-admin ← [{"apiGroup":"rbac.authorization.k8s.io","kind":"Group","name":"kubeadm:cluster-admins"}]

worker1$ sudo openssl x509 -in /var/lib/kubelet/pki/kubelet-client-current.pem -noout -subject -issuer   (kubelet 이 쓰는 인증서)
subject=O = system:nodes, CN = system:node:k8s-worker1
issuer=CN = kubernetes
worker1$ sudo kubectl --kubeconfig /etc/kubernetes/kubelet.conf auth whoami
Username system:node:k8s-worker1
Groups   ["system:nodes","system:authenticated"]
