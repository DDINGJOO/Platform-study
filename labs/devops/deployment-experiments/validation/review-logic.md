### 대조한 논리 경계

1. 할당 400명, 노출 320명, 전환 83명의 집합과 요청 수를 구분한다. 본문의 비율 정의는 전환 사용자 / 노출 사용자이며, 전체 할당 사용자를 분모로 삼는 분석과 다르다고 명시한다. 노출이 처리 영향을 받을 때의 선택 편향도 한정한다.
2. 중복 제거 키는 실험·사용자·이벤트 종류이며 request_id는 진단 정보다. 새 요청 ID와 같은 요청 ID의 재시도가 모두 고유 사용자 수를 늘리지 않는 설명이 저장 제약 및 실행기와 일치한다. 요청 시도 counter와 사용자 집합 gauge도 구분한다.
3. 새로고침·프로세스 재시작의 동일 실험·salt·볼륨 유지 조건을 설명한다. salt 변경 시의 재할당과 기존 실험 설정 기동 거부를 구분하며, 사용자 식별자·새 실험·새 실행에 따른 변경 가능성을 명시한다. 저장된 결과로 다른 실행까지 동일 집계를 보장한다고 확대하지 않는다.
4. 합성 전환이 사용자 번호·할당을 조건으로 생성됐음을 밝힌다. 그래프에서 승자 또는 제품 개선 효과를 추론하지 않으며 통계 판정을 후속 편으로 구분한다.
5. 도식의 400 → 320 → 83 및 1,600요청 / 400사용자, Grafana 캡션의 A·B 수치가 본문과 원시 자료에 일치한다. B의 37/160은 23.125%이며 두 출력의 반올림 차이도 원수치와 구분한다.

### 독립 재계산

스택을 다시 실행하거나 변경하지 않고 `out/events.json`에서 다음을 재계산했다.

- 할당 고유 사용자 400명과 이벤트별 고유 키를 확인했다.
- 각 이벤트 그룹이 저장된 할당 그룹과 같음을 확인했다.
- 모든 노출 사용자가 진입했고 모든 전환 사용자가 노출됐으며, 이벤트 시각 순서가 유지됨을 확인했다.
- A: 할당 202 / 노출 160 / 전환 46, B: 할당 198 / 노출 160 / 전환 37. `summary.json`과 일치했다.
- JSON 직렬화·SHA-256 앞 8바이트·modulo 10000 계산을 독립 구현해 전 사용자 bucket과 그룹을 확인했다. 변경 salt 재할당 수 182명도 일치했다.
- Python 파일 3개의 AST 구문 분석을 실행해 통과했다. LSP 도구는 제공되지 않아 실행하지 않았다.

파일·스택·증거 원본은 수정하지 않았으며 이 보고서만 작성했다. 재시작 전후 동일성은 저장된 실행기 assertion과 실행 결과에서 확인했고, 재실행해 새로운 증거로 교체하지 않았다.

### 대조한 논리 경계

1. 분모는 고정 모집 기간 안 최초 노출된 고유 사용자이며, 분자는 최초 노출 뒤 24시간 안의 고유 전환 사용자다. 진입·스팬·요청 수와 구분하고, 요청 기준 오류율·p95와도 다른 분모임을 명시한다. 같은 ID 재시도와 새 ID의 반복 사용자를 각각 중복 제거한다.
2. 노출 단계 SRM과 할당 단계 SRM을 구분한다. 노출 수가 같아도 무작위 할당의 증명이 아니며, 처리로 노출이 달라질 때 선택 편향과 ITT 검토가 필요하다고 한정한다. 2편의 선택된 노출 데이터를 사후 계획에 넣어 제품 효과로 판정하지 않는다.
3. SRM 기대 수는 전체 적격 노출에 예정 비율을 곱하며, 최소 표본 2,000명을 맞추기 위해 데이터를 잘라 비율 이상을 숨기지 않는다. 작은 기대 수는 SRM 확정 대신 보류한다. 사용자·기간·SRM·표본·가드레일·효과의 판정 우선순위가 본문·도식·코드에 일치한다.
4. 최소 2,000명은 검정력 계산 결과라는 주장을 하지 않는다. 기간과 전환 성숙 전에 보류하며, 고정 fixture 재검증과 유리한 제품 결과가 나올 때까지의 반복 실험을 구분한다. 순차 분석과 다중 검정이 구현되지 않았다는 한계도 명시한다.
5. +4%p 관측 효과와 Newcombe95 구간을 함께 설명한다. `관측 차이≥3%p`와 `하한>0`이 실제 효과≥3%p의 증명이 아니라는 점을 명확히 한다. 구간의 독립 이항 표본 가정과 근사 포함률의 한계도 뒤집지 않는다.
6. 오류율·p95의 관측값 문턱은 정책이며 무해성의 통계적 증명이 아니다. 요청 원자료 누락은 보류하고, 같은 전환율이라도 SRM 또는 가드레일 위반으로 다른 최종 판정을 내린다. 나머지 gate들도 보존하므로 앞선 보류 이유가 이후 조건을 충족했다는 뜻으로 바뀌지 않는다.
