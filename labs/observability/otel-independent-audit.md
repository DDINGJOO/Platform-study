# OpenTelemetry 시리즈 독립 원자료 감사

감사일: 2026-10-21. 작성자·네 관점 퇴고자와 다른 감사자가 공개 원자료를 직접 읽었다. 글은 수정하지 않았다. 01~04 첫 감사 뒤 05~08 심화판을 별도로 감사해 아래에 이어 기록했다. 판정은 8편 모두를 포함한다.

## 기준과 범위

- Java 고정 소스: `open-telemetry/opentelemetry-java`, `v1.67.0`, `b4b3a1b354425c3f1411173c0e48cb24a1cba224`. GitHub tag ref API를 독립 조회해 태그가 해당 commit을 직접 가리키는 것을 확인했다.
- Collector 고정 소스: `v0.163.0`, `5177a6a85ca3783068077e25aec6cebbe1d50d1f`. tag ref가 가리키는 annotated tag `f810321641f1506c0ba8c5131af98ebcdaa6d2fd`를 한 단계 더 조회해 대상 commit을 확인했다. Java instrumentation은 `v2.32.0`, `1b8644f8eb11d90295b1c313391aa84edeeec6e2`이며 tag ref가 해당 commit을 직접 가리킨다.
- 공식 웹 문서는 감사일의 응답을 직접 조회했다. Java 1.67.0 구현, 웹 사양 1.61.0, Micrometer 1.17.1, Micrometer Tracing 1.7.1, Reactor 3.8.7, Jaeger 2.22를 동일 버전으로 간주하지 않았다.
- 추가 조회한 OTLP 사양은 1.11.1, Alloy latest는 표시상 v1.21, OBI 소개의 최신 하이라이트는 v0.12.1이었다. 이를 고정 Java/Collector/agent 릴리스의 동작 보장으로 소급하지 않았다.
- 표의 글 위치는 `posts/CS/Observability/otel/` 아래의 편 번호와 HTML 원문 줄 번호다. 줄 번호는 감사 시점 기준이며 이후 편집으로 이동할 수 있다.
- 판정 단위는 핵심 논증을 구성하는 중요한 주장 묶음이다. 단순 문장 수나 전체 문장에 대한 완전성 보증이 아니다. 각 항목의 신뢰도는 높음이다.
- 확인: 원자료와 합치한다. 불일치: 원자료와 다르다. 확인 불가: 필요한 근거를 얻지 못했다. 과장: 관찰·계약보다 넓게 단정한다.

## 05~08 캡처·검증 증거

1. 4개 manifest의 캡처 8건에 대해 공개 raw 파일을 각각 독립 요청해 SHA-256을 계산했고 manifest의 full-file SHA-256과 8/8 일치했다. 줄 범위도 원문 안에 있었다. 이 manifest들에는 excerpt SHA-256 필드가 없으므로 excerpt 해시를 검사했다고 주장하지 않는다.
2. 캡처 PNG 8개 모두를 직접 열어 파일 경로·버전·줄 번호·보이는 코드 행을 해당 원문과 대조했다. `metric-reader`, `periodic-reader`, `pipeline-config`, `pipeline-graph`, `httpclient-matcher`, `httpclient-scope`, `span-limits`, `metric-cardinality` 모두 일치하며 주장에 필요한 분기를 가린 잘림을 발견하지 못했다. 01~04는 앞서 기록한 대표 4개 시각 검사의 범위를 유지한다.
3. 새 네 편의 고정 raw 링크는 manifest에 나온 일부 행만이 아니라 본문이 주장하는 caller·callee·분기도 직접 읽었다. 특히 Reader별 저장소, collect 이전 CAS, helper enqueue/종료, Future 보조 클래스, exemplar 원속성 전달은 코드 모양만 보고 추정하지 않았다.
4. Metrics 앱, Prometheus 서버, Collector YAML validate/배포·장애 주입, Java agent/OBI/Observation bridge 실행은 이번 독립 감사에서도 수행하지 않았다. source/계약 판정의 신뢰도는 높지만 해당 런타임 조합의 통과 증거는 없다. 글과 README가 이 제한을 숨기지 않았다는 판정이다.
