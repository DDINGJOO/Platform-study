# OpenTelemetry 구조와 설계 읽기: 작성 기준

2026-10-21에 시작한 로컬 초안 작업이다. 발행·커밋·푸시는 포함하지 않는다.

## 분류와 범위

- 공부 글: `posts/CS/Observability/otel/`, 업로드 분류 `Observability/OpenTelemetry`.
- 기여 회고: `posts/open-source-contribute/`. PR 재현·수정·리뷰 과정은 이쪽에 따로 쓴다.
- 설계자 입장에서 의도를 단정하지 않는다. 공식 문서가 밝힌 원칙, 특정 버전의 구현, 글쓴이의 해석을 구분한다.
- 미공개 보안 제보·비공개 포크·조직 자료는 사용하지 않는다. 이번 원자료는 공개 공식 문서와 공개 소스다.
- Java 구현 중심의 앞 네 편과 메트릭·Collector·자동 계측·데이터 의미를 다루는 뒤 네 편이다. Collector 전체나 모든 언어 구현을 검증했다고 하지 않는다.

## 공통 시리즈 박스

사용자 최신 요청에 따라 상단에는 현재 편을 포함한 최근 세 편만 표시한다. 1편은 1편만, 2편은 1·2편, 3편은 1·2·3편, 4편은 2·3·4편, 8편은 6·7·8편이다. 현재 편만 `b`로 감싸고 `&larr; 지금 이 글`을 붙인다. 별도의 전체 목차를 제공하지 않는다. 이 브리핑의 전체 집필 목록은 내부 작업 기준일 뿐이다. 초안에 존재하지 않는 공개 링크를 만들지 않는다. 아래는 4편의 정본이다.

```html
<div class="obsv-series">
  <div class="obsv-st">📚 OpenTelemetry 구조와 설계 읽기</div>
  2편. 스레드가 바뀌면 컨텍스트는 어떻게 이어질까<br>
  3편. 전송이 밀리면 스팬은 어디서 사라질까<br>
  <b>4편. 샘플링하면 무엇이 남고 무엇이 빠질까</b> &larr; 지금 이 글
</div>
```

## 글과 캡처의 기준

문제 → 공식 문서의 설명 → 실제 코드의 동작 → 얻는 점과 비용 → 확인 범위 순으로 쓴다. 만들어 보지 않은 실험·장애 경험·성능 수치를 실제 경험으로 쓰지 않는다.

코드는 위 커밋에서 가져오고, 캡처에 파일명·줄 번호·버전을 표시한다. 캡처 아래에 원문 permalink와 텍스트 풀이를 붙인다. PNG만 읽어야 이해할 수 있게 만들지 않는다. 사용자 최신 편집 요청에 따라 긴 SHA·문서 확인일·GitHub 화면이 아니라는 설명을 도입이나 각 캡처마다 반복하지 않는다. 제작 방식은 하단 참고 자료에서 한 번만 짧게 밝히며, 세부 해시·검증 과정은 lab에 보관한다. 실행하지 않은 실험을 실행했다고 쓰지 않는 원칙은 유지한다.

이미지는 편별 `images/01/`~`images/08/`에 두고 로컬 초안에서는 상대 경로로 참조한다. 아직 없는 CDN 주소로 바꾸지 않는다. 발행 전에 업로드 경로와 카테고리 존재 여부를 확인해야 한다.

집필은 `tistory-sketch-post`, 퇴고·독립 원자료 감사는 `blog-post-pipeline`을 따른다. 기존 글은 수정하지 않는다. 구조 검사·마스킹·원자료 감사·로컬 브라우저 미리보기의 결과를 구분해서 기록한다.

## 심화판의 필수 내용

- 대안은 같은 문제·같은 계층끼리 비교한다. OTel 전체, Collector, Prometheus 저장 서버, Micrometer 계측 API를 동급 대체품으로 취급하지 않는다. 조합 가능한 관계도 표시한다.
- 최소 두 가지 대안의 선택 기준과 반례를 구체적으로 설명한다. 표만 나열하지 말고 어떤 조건에서 결론이 달라지는지 쓴다.
- 소스의 짧은 한 함수로 전체 보장을 단정하지 않는다. 호출자→핵심 상태 변경→후속 처리 경로를 실제 고정 소스로 따라간다.
- 새 버전 권장과 읽고 있는 버전의 코드를 구분한다. 숫자 기본값·버전·지원 범위는 공식 문서나 고정 소스에 근거한다.
- 실패 사례를 가정하면 가정이라고 표시한다. 실제 실험 결과는 기록된 실행 로그만 인용한다. 성능·운영 비용을 실측하지 않았다면 그렇게 밝힌다.
- 내용에 맞으면 챕터와 코드 블록 수도 늘린다. 길이 때문에 사례·반례·한계를 잘라내지 않는다. 다이어그램은 정보 관계를 설명하는 데 필요한 만큼만 둔다.
