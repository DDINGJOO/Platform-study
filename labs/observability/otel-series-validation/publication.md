# OTel 8편 업로드 확인 기록

확인일: 2026-10-21. 사용자가 커밋·푸시·업로드를 요청하고 티스토리 카테고리를 생성한 뒤 진행했다.

## 반영 범위

- 콘텐츠 커밋: `5f294263e6566d65e78993ad9d311ce86c2e148d`, origin/main 푸시 확인.
- 대상은 `posts/CS/Observability/otel/`의 8편만이다. 카테고리는 `Observability/OpenTelemetry`다.
- 이미지 18개를 공개 저장소에 먼저 푸시하고 본문의 상대 PNG 참조를 실제 jsDelivr 주소로 바꿨다. 실험 자료 링크 7개도 공개 GitHub 주소로 연결했다.
- 기존 업로더로 1~8편을 순서대로 저장했다. 글 ID는 각각 681~688이며 [1편](https://dding-shark.tistory.com/681)과 [8편](https://dding-shark.tistory.com/688)에서 확인할 수 있다.

```sh
caffeinate -is /Users/dding/.local/share/tistory-uploader/venv/bin/python -u \
  .claude/skills/tistory-sketch-post/assets/tistory-upload.py sync \
  --only posts/CS/Observability/otel/ --limit 8 --visibility private
```

8편 모두 저장 직후 비공개·태그·본문 길이·SVG 검증에 통과했고 sync는 종료 코드 0으로 끝났다. 이후 사용자가 직접 공개로 전환했다고 확인했다. 공개 전환 후 검증은 읽기 전용이며 글을 다시 저장하거나 공개 범위를 변경하지 않았다.

매니페스트의 `visibility: private`은 마지막 업로더 저장 시점의 상태다. 현재 공개 상태와 혼동하지 않는다. 기존 업로더는 다음 수정 때 매니페스트 값이 아니라 실제 게시물의 공개 범위를 읽어 보존한다.

푸시 후 뒤늦게 대기열에 들어온 동일 콘텐츠의 자동 업로드는 중복 실행을 피하려고 취소했다. 작업·run 모두 취소 완료를 확인했다. 워크플로 설정과 전역 GitHub 인증은 변경하지 않았다.

## 확인 결과

- 업로드 전 [자동 검사](report.md): 8/8편 PASS, 정적·PC·모바일 오류 0건. 공개 원문 해시 18개 일치. 이 보고서의 매니페스트 불변 판정은 업로드 전 스냅샷이다.
- 최초 게시용 이미지 검사에서는 일부 이미지 미로딩과 탐색 시간 초과가 있었다. 동일 HTML로 다시 실행한 실제 CDN 브라우저 검사는 8편 모두 통과했다. 네트워크 응답을 가로채거나 로컬 이미지로 대체하지 않았다.
- 독립 읽기 전용 CDN 검사: 18/18 응답 HTTP 200, PNG 형식 정상, 응답 바이트 SHA-256이 로컬 원본과 일치.
- 실제 티스토리 페이지를 PC 1100×850, 모바일 390×844에서 검사했다. 16/16 화면 검사에서 이미지 18개가 정상 decode됐다. 두 화면을 합쳐 이미지 로딩 36회다.
- 같은 검사에서 현재 편 강조·안내, 최근 세 편 번호와 실제 이전 편 URL, lead, 종이색 배경, 표시 카테고리를 확인했다. 이전 편 링크는 4편에 2·3편, 8편에 6·7편만 존재한다. 별도의 전체 목차는 추가하지 않았다.
- 게시물의 태그·본문 길이·SVG 수를 업로더 기준으로 다시 검증했다. 8편 모두 현재 공개 상태에서 통과했다. 본문 길이 검사는 원문과 바이트 동일함을 의미하지 않는다.
- 별도 무인증 GET에서도 681~688 전체가 HTTP 200이며 실제 OTel 본문과 공개 상태를 확인했다.

## 변경하지 않은 것과 한계

기존 매니페스트 228개 항목과 이 시리즈 밖의 게시물은 그대로 보존했다. 새 글 번호 8개와 업로드 결과만 매니페스트에 추가했다. 로그인 쿠키·토큰·프로필과 조직별 마스킹 목록은 저장소에 넣지 않았다.

게시 화면 검사는 위 두 화면 크기의 이미지·링크·본문·스타일 확인이다. 모든 브라우저·스킨의 전체 시각 회귀나 외부 링크의 영구 가용성을 보장하지 않는다. CDN의 `@main` 주소는 변경 가능한 브랜치 참조다. OpenTelemetry 전체 통합·성능 검증의 한계는 [초안 검수 기록](editorial-summary.md)을 그대로 따른다.
