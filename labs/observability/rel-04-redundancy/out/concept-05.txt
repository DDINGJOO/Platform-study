== 1. 베타 인자 모형: 복제본 n개, 한 대의 비가용성 Q, 그중 공통 원인 비율 beta ==
공통 원인 사건 확률 = beta*Q (일어나면 n대 모두 다운)
독립 고장 확률 q 는 한 대의 비가용성이 정확히 Q 가 되게 맞춘다: q = (Q - beta*Q)/(1 - beta*Q)
시스템 비가용성 = beta*Q + (1 - beta*Q) * q^n

== 2. 감지 시간: HAProxy inter x fall ==
고장 시점은 검사 주기 안에서 균일하게 떨어진다고 가정. 첫 실패 검사까지 0~inter, 그 뒤 (fall-1)번 더 실패해야 DOWN
fastinter 를 주면 '내려가는 중' 상태의 간격이 fastinter 가 된다
 inter 2.0s fall 3 fastinter None: 감지 4.0 ~ 6.0초, 평균 5.00초
 inter 1.0s fall 3 fastinter None: 감지 2.0 ~ 3.0초, 평균 2.50초
 inter 2.0s fall 3 fastinter 0.5: 감지 1.0 ~ 3.0초, 평균 2.00초
 inter 1.0s fall 2 fastinter None: 감지 1.0 ~ 2.0초, 평균 1.50초
 inter 0.5s fall 3 fastinter None: 감지 1.0 ~ 1.5초, 평균 1.25초
 inter 5.0s fall 3 fastinter None: 감지 10.0 ~ 15.0초, 평균 12.50초

== 3. 감지 시간이 가용성에 주는 영향 ==
30일 99.99% 예산 = 259초 = 4.32분
 액티브-스탠바이, 고장마다 전체 트래픽: 실패 요청 비중 환산 15.0초 = 예산의 5.8%
 액티브-액티브 3대, 고장 난 한 대 몫: 실패 요청 비중 환산 5.0초 = 예산의 1.9%
 액티브-스탠바이, 감지 30초: 실패 요청 비중 환산 90.0초 = 예산의 34.7%
 회색 고장: TCP 검사가 못 잡아 사람이 20분 뒤 발견, 3대 중 1대: 실패 요청 비중 환산 400.0초 = 예산의 154.3%

== 5. 셀: 셀 10개, 셀 하나가 배포로 깨질 때 ==
 셀 1개: 나쁜 배포가 첫 셀에서 멈추면 영향 받는 요청 100%
 셀 4개: 나쁜 배포가 첫 셀에서 멈추면 영향 받는 요청 25%
 셀 10개: 나쁜 배포가 첫 셀에서 멈추면 영향 받는 요청 10%
 셔플 샤딩: 워커 8대에서 2대씩 고르는 조합 수 = 28 -> 한 조합의 몫 1/28 = 3.57%
