# OpenTelemetry 구조와 설계 읽기

공식 문서와 공개 소스를 읽고 구조와 비용을 이해하는 공부 기록이다. 설계자의 의도를 대신 설명하거나 기여한 PR의 성과를 소개하는 시리즈는 아니다.

상단에는 현재 편을 포함한 최근 세 편만 표시한다. 별도의 전체 목차는 두지 않는다.

Java `v1.67.0`, 커밋 `b4b3a1b354425c3f1411173c0e48cb24a1cba224`를 중심으로 읽는다. Collector는 `v0.163.0`, Java 자동 계측은 공개 릴리스 `v2.32.0`을 따로 고정한다. 정확한 SHA와 캡처 범위는 편별 `source-manifest.json`에 있다. 언어별 구현과 Collector의 세부 동작까지 같다고 일반화하지 않는다. 문서상 원칙, 코드에서 확인한 사실, 글쓴이의 해석을 구분한다.

각 편은 문제, 관련 코드 캡처, 코드 동작 분석, 얻는 점과 비용, 확인하지 못한 범위를 담는다. 캡처는 고정 커밋의 원문을 로컬에서 렌더링하며 파일명·줄 번호·원문 링크를 남긴다. PNG에는 별도 번역이나 수정 코드를 섞지 않는다.

코드 캡처·실험의 재현 자료는 `labs/observability/otel-*`에 둔다. 실제 실행한 검사와 소스만 읽은 분석을 구분한다. 작성 기준은 [공통 브리핑](../../../../labs/observability/otel-series-brief.md)에 있다.

## 분량보다 확인할 깊이

- 짧은 함수 소개로 끝내지 않고 호출자·상태 변화·후속 처리·실패 조건을 따라간다.
- Micrometer Observation/Tracing, Reactor, Go context, Prometheus, Jaeger, Alloy, eBPF를 같은 책임의 경계에서 비교한다. 조합 가능한 도구를 서로 배타적인 대체품으로 만들지 않는다.
- 선택 기준뿐 아니라 선택이 맞지 않는 반례를 적는다. API 중립성, 전송 호환성, 저장·질의 이식성을 구분한다.
- 직접 실행한 네 가지 Java 실험은 API/SDK 구성, Context 복원, 배치 큐 포화, 샘플링이다. 전체 시스템·성능·실제 백엔드 내구성 검증으로 확대하지 않는다.
- 본문·장 수의 상한을 두지 않는다. 사용자 요청에 따라 처음의 짧은 네 편을 심화하고 여덟 편으로 확장한다.

기존 `tracing-debugging`의 사용법·실습과 달리 이번 시리즈는 구현의 경계와 한계를 읽는 데 집중한다. 네 관점 독립 퇴고와 별도 원자료 감사, 로컬 브라우저 검사를 완료했다. 결과와 검증 한계는 [검수 기록](../../../../labs/observability/otel-series-validation/editorial-summary.md)에 남겼다. 후속 업로드와 게시 페이지 검증은 [발행 기록](../../../../labs/observability/otel-series-validation/publication.md)으로 구분한다.

## 발행 경로

사용자가 만든 `Observability/OpenTelemetry` 카테고리를 실제 업로더에서 확인했다. 여덟 편을 기존 업로더로 비공개 저장하고, 사용자가 직접 공개로 전환했다. 업로드한 글 번호와 확인 결과는 발행 기록을 따른다.

이미지 원본은 `images/01/`~`images/08/`에 보관하고 본문은 공개 저장소의 jsDelivr 주소로 참조한다. 원본을 main에 푸시한 뒤 18개 CDN 응답과 로컬 PNG의 해시 일치를 확인했다. 업로더가 로컬 경로를 자동 변환한다고 가정하지 않는다.
본문의 실험 소스·기록 링크도 공개 GitHub 주소로 연결했다. 상단 안내는 현재 편을 포함한 최근 세 편만 유지한다.

기여 과정은 별도 [open-source-contribute 계획](../../../open-source-contribute/ROADMAP.md)으로 분리한다.
