그러다 책의 사실 오류를 찾은 적도 여럿입니다. 다음 주제는 [ROADMAP](posts/CS/Observability/ROADMAP.md)에 있습니다.

그 밖에 소프트웨어 개발 생명주기(1편), 이 블로그를 자동화한 기록(2편)이 있습니다.

## 어떻게 쓰고 올리나

```
작성 → 퇴고 → 사실관계 감사 → 마스킹 검사 → 발행
```

1. **작성** · 글 한 편이 HTML 파일 하나입니다. 다이어그램은 손그림 느낌의 인라인 SVG 로 그립니다.
2. **퇴고** · 사실관계, 논리 모순, 독자 시점, 문장 일관성 네 가지 시선으로 따로 검토합니다.
3. **사실관계 감사** · 퇴고와 별개로, 글의 숫자·설정값·커밋·문서 인용을 원본과 하나씩 대조합니다.
   형식 검사를 다 통과하고도 결론이 틀린 글을 여기서 여러 번 잡았습니다.
4. **마스킹 검사** · 커밋 전에 pre-commit 훅이, 발행 전에 CI 가 한 번 더 봅니다.
5. **발행** · 업로더가 파일 해시로 새 글과 수정분을 판정해 올리고, 결과를 매니페스트에 기록합니다.
   매일 한 번 자동으로 동기화합니다.

## 공개 저장소라서 지키는 것

- 회사·조직을 특정할 수 있는 이름과 ID, 사람 이름은 싣지 않습니다.
- 비용은 절대 금액 없이 비율과 배수로만 씁니다.
- 아직 조치하지 않은 취약점은 쓰지 않습니다. 조치가 끝난 것만 과거형으로 씁니다.
