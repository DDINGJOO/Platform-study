# Tistory Sketch Post

티스토리 HTML 편집 모드에 그대로 붙여넣을 수 있는, 손그림 감성의 블로그 글을 만드는 스킬.
결과물은 항상 **단일 HTML 파일** 하나다 (외부 이미지 파일 없음 — 다이어그램은 전부 인라인 SVG).

## 왜 이 스타일인가 (지켜야 하는 이유)

이 스타일의 정체성은 세 가지 조합에서 나온다:
1. **종이 질감** — 크림색 배경(#fdfaf3) 위에 차분한 잉크색(#3d3a34) 본문
2. **손글씨 악센트** — 제목/캡션/다이어그램 라벨만 'Nanum Pen Script', 본문은 'Gowun Dodum'(가독성)
3. **스케치풍 SVG** — 자로 잰 직선 대신 살짝 삐뚤한 곡선. 머메이드나 기성 다이어그램 금지

셋 중 하나라도 빠지면 "그냥 HTML 글"이 된다. 특히 SVG를 `<rect>`와 직선으로 그리면
스타일이 즉시 무너지므로, 다이어그램 작업 전에 반드시 `references/svg-sketch-guide.md`를 읽는다.

## 작업 순서

### 1. 내용부터 확정한다 (스타일보다 먼저)

글의 사실관계, 논리 전개, 예시를 먼저 완성한다. 대화에서 이미 다룬 내용이면 그걸 쓰고,
새 주제면 조사부터 한다. 내용이 빈약한데 스타일만 예쁘면 이 스킬의 목적에 어긋난다.

### 2. 템플릿을 읽는다

`assets/template.html`을 Read로 읽고, 그 안의 `<style>` 블록을 **수정 없이 그대로** 사용한다.
클래스 이름(`obsv-*`)과 색상 팔레트를 임의로 바꾸지 않는다 — 시리즈 글 간 통일성이 생명이다.

### 3. 글 구조를 채운다

순서와 역할이 정해져 있다:

| 순서 | 요소 | 클래스 | 비고 |
|---|---|---|---|
| 1 | 시리즈 박스 | `.obsv-series` | 시리즈물일 때만. 현재 편을 `<b>`+"← 지금 이 글"로 표시 |
| 2 | 훅 도입부 | `p` 2~3개 | 아래 "훅 작성법" 참고 |
| 3 | 본문 챕터 4~6개 | `h2` | "1. 제목" 형식 번호. h2는 손글씨 폰트로 렌더됨 |
| 4 | 코드/데이터 | `.obsv-code` | 개념을 숫자·코드로 보여줄 때. HTML 특수문자 이스케이프 필수 |
| 5 | 콜아웃 | `.obsv-callout` | 지뢰 목록, 실무 팁, 주의사항. 제목에 이모지 1개 |
| 6 | 다이어그램 2~4개 | `.obsv-fig` + `.obsv-figcap` | 캡션은 "그림 N. 한 줄 통찰" 형식 |
| 7 | 요약 박스 | `.obsv-summary` | 글의 핵심을 2~3문장으로. 이걸로 글을 끝냄 |

**끝맺음 규칙**: 요약 박스가 마지막이다. "다음 편 예고" 문구는 넣지 않는다 (사용자가 명시적으로 뺀 요소).

### 4. 다이어그램을 그린다

글당 2~4개. 각 다이어그램은 장식이 아니라 **본문의 한 단락을 대체할 만큼의 정보**를 담아야 한다.
그리기 전에 `references/svg-sketch-guide.md`를 읽고 삐뚤한 패스, 손그림 화살표, 팔레트를 따른다.

다이어그램이 효과적인 지점: 대비(A vs B), 흐름(→ 단계), 폭발/규모(작은 것 → 큰 것), 구조(층/상자).
텍스트로 이미 충분한 내용을 SVG로 반복하는 건 낭비다.

### 5. 검증한다

작성 후 간단한 스크립트로 태그 짝을 확인한다 (티스토리는 깨진 태그에 관대하지 않다):

```python
html = open('post.html').read()
assert html.count('<svg') == html.count('</svg>')
assert html.count('<div') == html.count('</div>')
assert html.count('<path') == html.count('/>') + html.count('</path>')
```

### 6. SVG가 티스토리에서 깨지면 (비상 우회로)

인라인 SVG가 사라지고 라벨 텍스트만 남는 사고가 나면, 먼저 `references/svg-sketch-guide.md`의
"안전 문자" 절을 확인해 위험 문자를 제거한다. 그래도 안 되면 PNG로 내보낸다:

```bash
python3 .claude/skills/tistory-sketch-post/assets/svg2png.py <글.html> <출력디렉터리>
```

헤드리스 크롬으로 각 SVG를 2배 해상도 PNG로 뽑는다 (나눔손글씨 펜은 macOS에 기본 설치돼 있어 그대로 렌더된다).
그 후 `<div class="obsv-fig">` 블록을 자리표시자로 바꾼 "이미지판" HTML을 만들고,
티스토리 기본모드에서 각 자리에 PNG를 업로드해 삽입한다. **인라인 SVG가 되는 한 그게 우선이다** —
PNG는 반응형·선명도를 잃으므로 최후의 수단.

### 7. 전달한다

파일을 사용자에게 공유하면서 티스토리 업로드 방법을 한 줄로 안내:
"글쓰기 → HTML 모드 전환 → 전체 붙여넣기 → 기본모드에서 미리보기 확인"

## 글쓰기 톤

- **해요체 존댓말**. "~입니다"와 "~해요"를 섞되 "~해요" 비중을 높게. 딱딱한 문어체 금지
- 훅 작성법: 첫 문단은 개념 정의가 아니라 **구체적 장면이나 사건**으로 연다.
  좋은 예: "새벽 3시, 폰이 웁니다." / "청구서가 이해가 안 되는 순간이 옵니다."
  나쁜 예: "카디널리티란 집합의 크기를 의미합니다."
- 각 챕터는 "문제 제기 → 원리 → 트레이드오프 → 실무 적용" 흐름을 기본으로
- 핵심 문장은 `.obsv-mark`(형광펜)로 강조하되 **챕터당 1~2회만**. 남발하면 형광펜의 의미가 사라진다
- 비유를 적극 활용: "게시판에 숫자를 붙여둔다"(pull 방식), "예산이 타는 속도"(burn rate)처럼
  기술 개념을 일상 사물로 번역한 문장이 이 스타일 글의 시그니처다
- 요약 박스 마지막 문장은 글 전체를 관통하는 한 줄로: "신뢰성은 도덕이 아니라 예산 관리다"

## 분량 기준

본문 텍스트 2,500~3,500자(한글 기준), 챕터 4~6개, 다이어그램 2~4개, 코드블록 1~3개.
이보다 짧으면 깊이가 부족하고, 길면 한 편으로 소화가 안 되니 나누자고 제안한다.

**이건 편집상의 권고일 뿐, 기술적 상한이 아니다.** 파일 전체 크기에 상한을 두지 마라.

2026-08-05에 "티스토리에 크기 상한이 있다"는 가설로 파일 상한을 걸고 글을 쓰게 한 적이 있는데,
**그 가설은 반증됐고**(본문을 지워 줄여도 증상이 같았다) 대가만 남았다 —
다이어그램 두 개와 코드블록 하나가 지면 부족으로 잘려나갔다.
`references/svg-sketch-guide.md` 의 "티스토리에서 SVG가 사라질 때" 절 참고.

**내용을 지면에 맞추지 말고, 지면을 내용에 맞춰라.** 그림이나 코드블록을 뺄 이유는
"공간이 없다"가 아니라 "본문이 이미 그걸 충분히 말했다" 하나뿐이다.
정말 길어지면 편을 나누되, 그건 크기 때문이 아니라 주제가 둘이기 때문이어야 한다.
