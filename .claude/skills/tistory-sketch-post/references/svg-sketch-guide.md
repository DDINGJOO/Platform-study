# 스케치풍 SVG 그리기 가이드

이 스타일의 SVG는 "사람이 펜으로 슥슥 그린 화이트보드 그림"처럼 보여야 한다.
자로 잰 듯한 `<rect>`, `<line>`, 정원 `<circle>`을 나열하면 즉시 기성 다이어그램 느낌이 나므로 금지.

## 핵심 원리: 모든 선을 살짝 삐뚤게

직선을 긋고 싶으면 `<line>` 대신 **제어점이 2~4px 어긋난 베지어 곡선**을 쓴다.

```
직선 대신:  <path d="M70 85 C 110 84, 140 86, 175 85" stroke="..." fill="none"/>
                            ↑ y좌표를 ±1~3px 흔든다
```

상자를 그리고 싶으면 `<rect>` 대신 네 변을 각각 곡선으로 잇는 닫힌 패스:

```
<path d="M30 50 C 100 47, 170 51, 230 48     ← 윗변 (y가 47~51 사이에서 출렁)
         C 233 78, 232 96, 231 118           ← 오른변
         C 170 121, 100 117, 32 119          ← 아랫변
         C 29 96, 30 72, 30 50 Z"            ← 왼변, 닫기
      fill="#fffdf7" stroke="#4a7fb5" stroke-width="2.6"/>
```

요령: 시작/끝 좌표에서 1~4px씩 어긋난 제어점을 넣는다. 흔들림이 5px를 넘으면 지저분해지고,
0이면 기계 느낌이 난다. `stroke-linecap="round"` `stroke-linejoin="round"`를 기본으로.

## 손그림 화살표

marker를 하나 정의해서 재사용한다. 화살촉도 곡선이다:

```xml
<defs>
  <marker id="arr1" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse">
    <path d="M 1 1.5 C 4 3, 6 4, 8.5 5 C 6 6, 4 7, 1 8.5" fill="none" stroke="#3d3a34" stroke-width="1.6" stroke-linecap="round"/>
  </marker>
</defs>
<path d="M300 70 C 335 72, 355 85, 385 105" fill="none" stroke="#3d3a34" stroke-width="2" stroke-linecap="round" marker-end="url(#arr1)"/>
```

- 화살표 몸통도 곡선으로 (살짝 호를 그리며)
- 점선 강조는 `stroke-dasharray="1 7"` (점점점 느낌) 또는 `"8 8"` (파선)
- **같은 marker id를 한 파일 안에서 중복 정의하지 말 것** — SVG가 여러 개면 id를 arr1, arr2...로 구분

## 팔레트 (고정)

| 용도 | 색 |
|---|---|
| 잉크(기본 선, 텍스트) | `#3d3a34` |
| 파랑 (A측, 중립 개념) | `#4a7fb5` |
| 초록 (긍정, 성공, 저장) | `#5a9e6f` / 진한 라벨 `#2e6b41` |
| 빨강 (위험, 에러, 부정) | `#e5533c` / 진한 라벨 `#b3502f` |
| 주황 (주의, 중간 단계) | `#e5a33c` / 진한 라벨 `#c07f18` |
| 회색 (보조 설명) | `#8a8272` |
| 상자 채움 | `#fffdf7` (기본), `#fbeee7` (빨강 계열), `#fdf3dd` (주황 계열) |
| 형광펜/폭발 | `#ffd54d` |

의미와 색을 일치시킨다: 좋은 것은 초록, 나쁜 것/범인은 빨강, 주인공 개념은 파랑.

## 텍스트

- 다이어그램 라벨: `font-family="'Nanum Pen Script', cursive"` 크기 17~27
- 코드/데이터 라벨: `font-family="Menlo, monospace"` 크기 10~14
- 이모지를 라벨에 1개씩 곁들이면 손그림 감성이 살아난다 (💾 🗑️ 📟 🔥 ⏳ 등). 남발 금지
- 핵심 결론은 다이어그램 하단에 빨강(#b3502f) 손글씨 한 줄로: "= 저장 비용 대신 인프라 비용을 낸다"

### 안전 문자만 쓴다 (티스토리 렌더링 사고 방지)

`<text>` 노드에 낯선 유니코드를 넣으면 티스토리에서 **그 SVG만 통째로 사라지고 텍스트만 남는** 사고가 난다.
2026-08-04에 실제로 발생 — `≠`(U+2260)와 `─`(U+2500)를 쓴 그림 두 개가 로컬에서는 정상인데 티스토리에서 깨졌다.
태그·속성·크기는 정상 발행된 글과 완전히 동일했고, 유일한 차이가 이 두 글자였다.

| 검증된 안전 문자 | 쓰지 말 것 |
|---|---|
| `→` `—` `·` `✅` 이모지, 한글, ASCII | `≠`(→ "A는 B가 아니다"로 풀어쓰기), `─`(→ `→` 또는 ASCII `--`), 그 외 박스드로잉·수학기호 |

원칙: **화살표는 `→`, 대시는 `—`, 나머지 기호는 말로 풀어쓴다.** 기호 하나 아끼려다 그림 전체를 잃는다.

## 캔버스 규칙

- `viewBox="0 0 700 H"` (H는 내용에 맞게 170~430), `style="width:100%;max-width:700px;height:auto;"` → 반응형
- 좌우 여백 20~30px 확보. 텍스트가 700을 넘어 잘리지 않는지 좌표 검산
- 한 SVG에 개념 하나만. 욕심내서 두 개념을 넣으면 둘 다 안 보인다

## 자주 쓰는 구도

1. **A vs B 대비**: 위아래 두 상자(또는 좌우), 각각 장단점 라벨. 점선으로 중앙 분리
2. **흐름도**: 상자 → 화살표 → 상자, 3~5단계. 각 상자 아래 회색 보조설명
3. **폭발/규모**: 평온한 수식 → 빨간 상자(원인) → 별모양 폭발 도형(`L` 명령으로 뾰족하게) + 결과 숫자
4. **층 구조**: 상자를 세로로 쌓기. 각 층에 "역할: 설명" 라벨
5. **그래프**: 축 2개(삐뚤한 패스) + 출렁이는 데이터 선 2~3개. 기울기 비교에 효과적

## 마무리 검증

- svg/path/text 태그 짝 확인 (`<path ... />` 셀프클로징 권장)
- `&` `<` `>`가 텍스트 노드에 raw로 들어가지 않았는지 확인 (`&amp;` 등으로)
- viewBox 높이와 실제 내용물 y좌표 범위가 맞는지 (아래가 잘리는 사고 방지)
